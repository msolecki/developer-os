Wave 3 writes `compose` and binds the production ports. Wave 4 adds rollback over the same composer.
Wave 5 is the end-to-end proof, and wave 6 closes the plan.

(`packages/core/src/update/`) and CLI participants (`apps/cli/src/update/`).

## Founder questions

Each recommendation is option A, and the amendment is written with it. A different answer changes
only the item the question names.

- **Q1 — the source of the three retained signed-metadata documents (P4).**
  - **A (recommended):** Carry the bytes inline as construction `plan_derived` rows
    (`release_metadata_after`) and withdraw `guarded_signed_metadata`. The plan reproduces the bytes on
    every recovery. The cost is about 41 MiB of the 512 MiB construction-plan cap.
  - B: The same, but keep the arm as a validated, unreachable residual (§13.3 item 11), as the
    `symlink` arm is. That keeps dead validator code and an extra exact-set test.
  - C: Retain the three files in the planning scratch envelope. This needs changes to the scratch
    validator, cleanup and recovery, and a crash that loses system temp makes the source vanish.
- **Q2 — the Codex executable and environment for re-registration (P6, NEW-61).**
  - **A (recommended):** Use `CODEX_HOME` plus `TMPDIR`, matching the install path that has been
    observed to work. Pin the canonical real path, owned by the user or root, with no group or other
    write on it or any ancestor. Homebrew and npm `codex` installs work.
  - B: Keep the owner-owned single-link rule. Every Homebrew or npm `codex` refuses, so update never
    re-registers in practice and NEW-61 stays open.
  - C: Update runs no effect and leaves the registration `stale`, and `doctor` tells the user to rerun
    `developer-os init`. Update then silently ships skills that Codex does not load until the user acts.
- **Q3 — the resumed-run exit class (P7(b), Phase 8 review I2).**
  - **A (recommended):** Add a `compensationCause` field to the V2 coordinator journal. It changes the
    codec, bounds and fixtures, and adds about 60 bytes per journal.
  - B: On resume, infer the cause from a compensating `target_verifier` step. There is no format
    change, but an I/O failure at that step would be reported as a rejection, exit 5.
  - C: Accept it as a residual. A crash during automatic rollback exits 1 instead of 5.
- **Q4 — the planner and verifier capability gate (P7(c), Phase 8 review M1).**
  - **A (recommended):** Drop the spawn-time scan and keep the repository-level graph gate
    (§2; accepted residual 6). A real planner or verifier can run.
  - B: The bundle manifest names a pure module and the spawn-time scan checks only that module. This
    adds a manifest field and signing-time work in A16.
  - C: Keep the scan as it is. No real planner or verifier can ever pass, because each reads stdin.
- **Q5 — the production binding while Task 11b is parked (P7(d)).**
  - **A (recommended):** Bind every production port now. The fallback-handoff port refuses
    `update_fallback_unavailable`, exit 4, before allocation until 11b fills it. The code path is real,
    and only the handoff is missing.
  - B: Leave `apply` unbound in production and compose only in the fixture. Closure Task 9's
    "production binding" stays open.
  - C: Unpark 11b now. This first needs the D46 root-key decision.
- **Q6 — the scope of the Task 26 proof.**
  - **A (recommended):** Cover install, update, rollback, reapply and uninstall on the synthetic
    fixture for both architectures. The Git and automation leg runs in the `*.pinned-host.test.ts`
    lane (D59 Q5-A) until NEW-113 lands. Both specs stay, because 11b, NEW-112 and NEW-113 still
    depend on them. DOS-P7's gate closes on the fixture only.
  - B: Wait for NEW-113 and run the archived Task 26 as written. That delays Task 26 until after
    Phase 9's gate.

## Global Constraints

- **Lane (D70):** tasks write tests but do not run them. A task commit runs `npm run lint` only. The
  full suite (`npm run check` and every deferred slow suite) and the fresh-context review run at plan
  close (Task 12). Tick a "run" step as "deferred to plan close (D70)". D70 is cited from the dispatch
  and is not yet recorded in the roadmap.
- Implementers work one worktree each under `../developer-os.worktrees/<task>`, branch `task/<task>`
  from `development`. They commit code and tests only, never edit `docs/superpowers/`, and never push
  or merge (`SESSION.md` §4.1).
- The spec wins over this plan. A step that contradicts the approved amendment is a stop condition
  (`SESSION.md` §4).
- Every filesystem mutation follows `plan → backup → stage → validate → apply → verify → finalize`.
  Identity comes from recorded evidence (construction journal, construction evidence, persisted plan),
  never from a use-time `lstat` taken as authority.
- No test reads a live Brain, vendor home, credential store or launcher install. Fixtures are
  synthetic, with Ed25519 test keys (`apps/cli/src/update/testing.ts`).
- Package direction stays `core ← security ← platform-macos ← cli`. Core gains no filesystem or
  process imports.
- Stage exact paths only. `docs/superpowers/` is globally gitignored: use `git add -f <path>`.

## Review Focus

1. A fresh process recovers after dying between the creation of `update/source/bundle` and source
   staging. The parent's identity comes from the construction journal, and a swapped inode refuses
   as exit 6 (Task 1).
2. A home with no ephemeral reservation files at all (for example, no `state/git-sync.json` or
   `state/update-rollback.json`) plans and applies an update. This is the normal real home, and every
   shipped test pre-creates them (Tasks 3 and 11).
3. `codex` is a Homebrew symlink and the Codex home is not `~/.codex`. The refresh runs against the
   right home and the registration record reads `registered` afterwards (Task 6).
4. A run that died during automatic rollback after a verifier rejection resumes and exits 5 with
   "version X is still active", not 1 (Task 4).
5. A terminal manifest that differs from the transitional one by anything except the retired
   partition refuses as exit 6 before the terminal rename (Task 7).
