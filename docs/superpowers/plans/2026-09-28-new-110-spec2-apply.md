## Global Constraints

- **Lane (D70):**
  - Tasks write their tests but do not run them.
  - A task commit runs `npm run lint` only. It covers build, typecheck and lint, so every task must
    leave the tree compiling.
  - The full suite and the fresh-context review run at plan close (Task 14).
  - Tick a "run" step as "deferred to plan close (D70)".
- **Implementers:**
  - One worktree each, under `../developer-os.worktrees/<task>`, on branch `task/<task>` from
    `development`.
  - They commit code and tests only. They never edit `docs/superpowers/`, and never push or merge
    (`SESSION.md` §4.1).
  - The orchestrator cherry-picks each task in dependency order.
- **One file owner per wave.** Two tasks in the same wave never touch the same file. The `Where:`
  lines below are exhaustive for writes; a task that finds it must write another file stops and asks.
- **The spec wins over this plan.** A step that contradicts the D72 block is a stop condition
  (`SESSION.md` §4).
- **Mutations and identity.** Every filesystem mutation follows
  `plan → backup → stage → validate → apply → verify → finalize`. Identity comes from recorded
  evidence (the construction journal, construction evidence, the persisted plan), never from a
  use-time `lstat` taken as authority.
- **Test isolation.** No test reads a live Brain, vendor home, credential store or launcher install.
  Fixtures are synthetic, with Ed25519 test keys (`apps/cli/src/update/testing.ts`). Tests that run a
  real `init` run one at a time (`SESSION.md` §4.1).
- **Package direction** stays `core ← security ← platform-macos ← cli`. Core gains no filesystem or
  process imports.
- **Staging.** Stage exact paths only. `docs/superpowers/` is globally gitignored, so use
  `git add -f <path>`.

## Review Focus

1. **Recovery between parent creation and source staging.** A fresh process that died between
   creating `update/source/bundle` and staging the source resolves the parent from the construction
   journal. A swapped inode refuses, exit 6 (Task 1).
2. **A home with no ephemeral reservation files.** With no `state/git-sync.json` and no
   `state/update-rollback.json`, the update still plans and applies. Every shipped test pre-creates
   these files (Tasks 3 and 10).
3. **A non-default Codex install.** When `codex` is a Homebrew symlink and the Codex home is not
   `~/.codex`, the refresh targets the right home and the record reads `registered` afterwards
   (Task 6).
4. **Resume after an automatic rollback.** A run that died during automatic rollback after a verifier
   rejection resumes and exits 5, not 1 (Task 4).
5. **A terminal manifest with an unexpected difference.** If the terminal manifest differs from the
   transitional one by anything other than the retired partition, it refuses with exit 6 before the
   terminal rename (Task 7).
