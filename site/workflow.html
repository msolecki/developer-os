Workflow at a glance

An agent session forgets. The vault remembers. You decide what stays. developer-os connects every session to two durable places: an Obsidian vault for knowledge that outlives the project, and the repository for the plan and the code. New knowledge enters through _inbox/ and becomes trusted only after you approve it.

vault knowledge into the session a new decision into _inbox/ plan and code into the repository

The daily loop

Nothing in the loop runs on its own: you start every skill. Hooks only remind and guard. Select a step, or let the loop play. The full text is in How to work: brain + code.

    The life of a note

    The agent writes only to _inbox/. Everything after that happens in brain-review, after your yes, and nothing is deleted. Pick a review decision to see where the note goes and how its frontmatter changes.

    _inbox/status: inbox · a draft, not a fact
    DEV/ · PROJECTS/status: active · trusted knowledge
    _archive/status: archived · out of search, recoverable
    queue-sqs.md
    type: decision
    status: active
    queue-kafka.md
    type: decision
    status: inbox
    summary: "Events go through Kafka"

    Hooks in one session

    Small Python scripts with no dependencies and no network. They ask instead of blocking, and stay silent when they fail. Details are in the hooks reference.

    From idea to merge

    The repository remembers the code. The plan lives in docs/plans/ and is deleted once every step is in a commit; a reviewer other than the author checks the work before it merges.

    spec→ audit-to-backlog→ implement-backlog→ code-review→ pr-cycle→ docs-sync→ session-retro

    Vault or repository? A decision, lesson or reference that you or another project will look for again goes to the vault. A plan, an ADR or a fact about the code stays in the repository: a plan in the vault drifts away from the code it describes. See Vault or repository?
