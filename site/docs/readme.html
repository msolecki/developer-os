developer-os

Source: README.md

A Claude Code plugin for working with an AI coding agent and an Obsidian vault as its long-term memory. Agent sessions forget everything between runs; developer-os gives the agent skills to search your vault before it starts, capture decisions into an inbox while it works, and help you review and tidy what was captured. You approve what becomes knowledge. The plugin is Markdown (skills, agents, output styles and rules) plus three small POSIX sh hook scripts, with no server, no database and no runtime to install. Codex support is manual and best-effort.

Install (Claude Code)

/plugin marketplace add msolecki/developer-os
/plugin install developer-os@developer-os

The plugin has no version number. An install takes the latest commit of development, and claude plugin update developer-os@developer-os picks up every later commit. Auto-update is off for this marketplace unless you turn it on under /plugin → Marketplaces.

Set up the vault

Run the brain-setup skill in Claude Code: it copies plugin/vault-template/ (or connects an existing vault), shows the two config edits as a diff and applies them after you approve. The two edits are one line in ~/.claude/CLAUDE.md:

Brain vault: /absolute/path/to/your/vault

and the vault path in permissions.additionalDirectories in ~/.claude/settings.json, so Claude Code may read and write it from any project.

For project repositories, start from the files in templates/project/. They include a docs/ skeleton; run the docs-sync skill to fill and check it. The full setup, with Obsidian settings and a first test, is in docs/workflow.md.

What the hooks do

The plugin has three hooks. On every SessionStart (startup, resume, /clear, compaction and fork), in every project, it runs plugin/hooks/session-start.sh, which prints plugin/rules/core.md; the output becomes session context. After a compaction or a resume inside a git repository it adds a state card of at most 1 KB: the branch, a Newest plan: line, docs/plans/.devos-state.md (the task state that implement-backlog, pr-cycle and audit-to-backlog keep there; hidden once it is older than 7 days), then up to 10 worktrees. A longer card is cut at a whole line and ends with a cut marker. Installing the plugin therefore changes how the agent behaves everywhere, not only when you call a skill; read core.md for the rules themselves.

To turn it off, disable the plugin (/plugin, then disable developer-os). To keep the plugin but change a rule, override it explicitly in your user-level ~/.claude/CLAUDE.md (for example, "Ignore the developer-os rule on plan files"); that file loads alongside the core rules in every session.

A Stop hook (plugin/hooks/capture-nudge.sh) counts tool calls in the session transcript and reads only background-task and Monitor ids, output-file paths and Monitor start times from it, never message content. Once per session, after 30 tool calls, and not while a background agent, command or Monitor it can see is still running, it asks the agent to run the session-retro skill, which proposes a wrap-up and applies only what you approve. Set DEVELOPER_OS_CAPTURE_NUDGE=off to turn it off, or DEVELOPER_OS_CAPTURE_NUDGE_MIN=<n> to change the threshold.

A PreToolUse hook on Bash (plugin/hooks/guard.sh) asks for confirmation (it never blocks) before a dependency install with a package argument (npm|pnpm|yarn|bun install|add|i <pkg>, an npm alias such as npm in, or the binary by full path), a git push with --force, -f or a +refspec (even next to --force-with-lease; a lone --force-with-lease passes; git also by full path), and a hook bypass: --no-verify or a prefix of it such as --no-veri, git commit -n, HUSKY=0 or core.hooksPath in any form. In claude -p an ask resolves to a denial.

All three are POSIX sh (plus grep -o and head -c, which macOS and Linux provide), need no jq, make no network calls and fail open: on input they cannot parse or any error they exit silently and the normal permission flow applies.

What's inside

  • Brain skills: brain-setup, brain-search, brain-capture, brain-review, brain-garden, brain-compile. They read and write the vault with the agent's own file tools.
  • Engineering skills: code-review, spec, audit-to-backlog, implement-backlog, fix-pr, pr-cycle, bug-triage, deploy-checklist, instruction-review (add --prune for a periodic cut), plan-status, client-reply, docs-sync, project-baseline.
  • Session skills: session-retro (end-of-session wrap-up: state check, cleanup proposals, Done / Not done / Needs you, plan update or close, approval-gated capture) and skill-usage (read-only report of how often each developer-os skill fired locally, with keep/merge/rewrite-description/remove suggestions).
  • Conventions skills (load only when relevant): comments-conventions, error-handling-conventions, defensive-coding-conventions, monitoring-conventions, nextjs-conventions, testing-conventions, typescript-conventions.
  • Built-in overlaps: /code-review, /security-review, /recap, /insights, /goal, /skill-doctor and /doctor cover similar ground; when to use which.
  • Agents: code-reviewer, performance-engineer, qa-expert, research-analyst, security-auditor.
  • Output styles: architect, debug, direct-objective, tdd-enforcer. Select one with /output-style, or set "outputStyle": "developer-os:architect" in settings (the plugin prefix is required).
  • Three hooks: SessionStart loads plugin/rules/core.md (plus a state card after compaction), Stop suggests a session wrap-up once per long session, PreToolUse asks before installs, force pushes and hook bypasses (see above).
  • Evals: behavior checks for the brain skills, code-review, session-retro and the skill triggers in evals/, run by hand with claude plugin eval. Not part of the plugin payload.

Codex (installer, best-effort)

There is no Codex manifest. From a clone of this repository (or the marketplace copy in ~/.claude/plugins/marketplaces/developer-os), run:

scripts/install-codex.sh --dry-run   # show what would change
scripts/install-codex.sh             # install or update
  • It writes a Codex copy of every skill to ~/.agents/skills/<name> (set CODEX_SKILLS_DIR for another location, such as ~/.codex/skills/ on older Codex versions). Each copy keeps only name and a short description (the first sentence and the quoted trigger phrases, or the "Use when" sentence when there are none), so all of them fit Codex's 8000-character skill list, and has its Claude-only references rewritten. A skill description must be one plain line; the installer refuses any other form before it writes anything.
  • It puts plugin/rules/core.md and your Brain vault: line (--vault <path>, else the line already in the block, else ~/.claude/CLAUDE.md; pass --vault again to change it) between developer-os-core markers in ~/.codex/AGENTS.md ($CODEX_HOME/AGENTS.md when CODEX_HOME is set; --project <dir> for a project's AGENTS.md). Text outside the markers stays; a changed file is backed up first.
  • Run it again after each plugin update. An untouched copy of a skill the plugin no longer has, made from this checkout, is removed. --uninstall removes only what it installed; --project <dir> --uninstall removes only that project's block and keeps the skills. A skill directory it did not create, including an older hand-made symlink into another clone, is skipped and reported; remove it first to let the installer manage it.

This setup is not tested on releases. The hooks, agents and output styles have no Codex equivalent; see Claude-only features.
