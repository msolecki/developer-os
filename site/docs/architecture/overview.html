Architecture overview

Source: docs/architecture/overview.mdVerified 2026-10-16

developer-os has no process of its own. Its architecture is what Claude Code loads, when, and what the agent then reads and writes on the user's behalf.

1. Repository layout

.claude-plugin/marketplace.json   marketplace: one plugin, source ./plugin
plugin/                           the installed payload
  .claude-plugin/plugin.json      name, version, description, license, keywords
  rules/core.md                   core rules, printed by the SessionStart hook
  SURFACE.txt                     public names, checked against the disk
  hooks/hooks.json                three hooks, 10-second timeouts
  hooks/session-start.sh          SessionStart: core rules, state card after compaction
  hooks/guard.sh                  PreToolUse guard for Bash
  hooks/capture-nudge.sh          Stop hook: session wrap-up nudge
  skills/<name>/SKILL.md          28 skills
  agents/<name>.md                5 agents
  output-styles/<name>.md         4 output styles
  vault-template/                 copied by brain-setup
templates/project/                project template (not installed)
scripts/install-codex.sh          Codex installer, run by hand (not installed)
evals/                            claude plugin eval cases (not installed)
tests/*.test.sh                   hook tests
.agnix.toml                       agnix lint settings for CI

docs/                             this documentation; docs/plans/ is git-ignored

Only plugin/ reaches a user's machine through the marketplace. templates/ and evals/ stay in the repository; skills that mention them say so.

2. Load model

What occupies the context of a session, and when:

PartWhen it loadsSize todayLimit
rules/core.mdEvery SessionStart: startup, resume, /clear, compaction, forkJust under the limit (figure in CURRENT-STATE)8192 bytes (scripts/check.sh); Claude Code caps hook output at 10,000 characters

The fixed cost per session is the core rules plus the listings. Everything else is paid only on use, which is why conventions live in skills and not in the core rules.

3. Hook pipeline

  • session-start.sh prints core.md, then, for source compact or resume inside a git repository, the branch, the newest plan, docs/plans/.devos-state.md (skipped when older than 7 days) and the worktrees, cut to whole lines within 1024 bytes.
  • guard.sh extracts tool_input.command with sed, unescapes JSON, joins line continuations, drops quotes, splits on semicolons, newlines, ampersands, pipes, parentheses and backticks, and scans each segment with awk. Quotes are stripped on purpose, so a mention inside a commit message also asks. Any parse failure prints nothing.
  • capture-nudge.sh reads session_id and transcript_path from the input, counts "type":"tool_use" occurrences in the transcript file with grep, defers while a background task launched in the session has no <task-notification> and a fresh output file under a tasks/ directory, or while a Monitor started in the last 30 minutes has no terminal notice, and records a per-session marker in ${CLAUDE_PLUGIN_DATA:-${TMPDIR:-/tmp/<uid>}}/capture-nudge/ so it fires once. Markers older than 7 days are removed.

Exact inputs, outputs and switches: reference/hooks.md.

The plugin makes no network call itself. What the agent reads becomes model context; an agent with web tools could send it further, which the plugin cannot prevent (SECURITY.md).

6. Trust boundaries

BoundaryUntrusted inputControl
Vault notesText a past session or a phone capture wroteSkills treat notes as data and never run commands or open URLs from them; phone captures arrive in _inbox/
PR review comments, issues, CI logs, code commentsAnyone who can comment, file an issue or push codefix-pr, pr-cycle, bug-triage and code-review treat them as data and flag text that tries to instruct the agent; fix-pr flags non-collaborators; four injection-* evals check it
Code, diffs, fixtures, fetched pagesThe reviewed repository or the webEvery agent prompt states they are data; research-analyst never fetches a URL built from local file contents
External repositories.claude/settings.json, hooks, .mcp.json of a client or OSS repoCore rule: read them before the first session, use a sandbox or plan mode, never copy them into user config unread
Subagent outputA delegate's editsCore rule: auth/2FA/security changes from a subagent are unauthorized until reviewed; compare git status and git diff
Plugin updatesA new commit's hooks and rulesSECURITY.md: review the diff from the installed commit before updating; auto-update is off by default
Session transcriptsPast conversationsOnly skill-usage reads them, and only counts; session-retro and docs-sync never open them

7. Validation

scripts/check.sh is the single local gate, run before every commit and by .github/workflows/check.yml (after an agnix lint step) on pushes to development and main and on pull requests. Its stages and prerequisites are in development.md. Behavior is checked separately by the evals, by hand (evals/README.md).
