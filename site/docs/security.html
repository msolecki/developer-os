Security policy

Source: SECURITY.md

Supported versions

Releases are tagged v<version> and listed in CHANGELOG.md; the marketplace serves the latest one from main. Only the latest release receives security fixes.

Reporting a vulnerability

Report privately through GitHub security advisories: https://github.com/msolecki/developer-os/security/advisories/new

Never report a vulnerability in a public issue.

Include:

  • the installed version (version of developer-os@developer-os in ~/.claude/plugins/installed_plugins.json),
  • the steps that reproduce the problem,
  • the expected result and the actual result.

Never include the content of a vault or a secret. Describe it instead.

Scope

  • The plugin is Markdown (skills, agents, output styles, rules) plus 5 hooks in plugin/hooks/hooks.json: SessionStart runs cat on plugin/rules/core.md and, after a compaction or resume, state-card.py, which prints the git branch, newest plan, docs/plans/.devos-state.md and worktrees of the working directory, and on a new session notices.py, which reads the plugin version, the Brain vault: line of the user-level CLAUDE.md, the first 2 KB of _inbox/ notes and the last line of _reports/garden-log.md, and shows counts and dates, never note names; Stop runs capture-nudge.py, which counts tool_use entries in the session transcript and reads only background-task and Monitor ids, output-file paths and Monitor start times from it, never message content; PreToolUse runs guard.py on Bash commands and can only ask for confirmation. The four scripts are Python 3 with the standard library only, make no network calls and fail open. The plugin ships no binary, server or network code.
  • Updates come from this Git repository through the Claude Code plugin marketplace: each update installs the latest release from main. An update can change plugin/hooks/hooks.json and the hook scripts, which run in every session. Review the diff between the two release tags before you update (git diff v<installed>..main in a clone); auto-update is off for this marketplace unless you turn it on.
  • The skills treat vault notes, pull request comments, diffs and fetched web pages as data, never as instructions.
  • What the agent reads from the vault goes to your model provider as session context, like any other file. An agent with web access could also send it elsewhere; the plugin cannot prevent that.
