developer-os
How it works Skills Install GitHub

Your coding agent forgets. Your vault doesn't.

developer-os is a Claude Code plugin that gives the agent an Obsidian vault as long-term memory, a short set of working rules for every session, and guard rails that ask before risky commands.

/plugin marketplace add msolecki/developer-os
/plugin install developer-os@developer-os

Plain Markdown and three small shell scripts. No server, no database, nothing to run. MIT licensed.

How it works

Every new agent session starts from zero. What you explained yesterday, the bug you chased for an hour, the reason you picked one library over another: gone. developer-os splits what should survive into two places and keeps you in charge of both.

The vault remembers knowledge

An Obsidian vault holds decisions, lessons and references that outlive a single task or repository. The agent searches it before large tasks and cites the notes it used.

The repository remembers the code

Plans, decision records and code facts stay next to the code they describe. Plans are git-ignored working files, deleted when the task is done.

You decide what becomes knowledge

The agent creates notes only in the vault's _inbox/. It edits or moves any other note only after you approve. An unreviewed agent note is a draft, not a fact.

Rules that load in every session

Installing the plugin changes how the agent behaves everywhere, not only when you call a skill. At session start a hook prints core.md, a rule file kept under 8 KB so it never crowds out your own context. A few of the rules:

  • Run lint, types and the changed area's tests before each commit; the full suite before a push or PR.
  • Never delete or skip tests to make a build green.
  • Write a plan before changing more than 50 lines of code, and keep it updated so work survives a context reset.
  • Code written by an agent gets reviewed by a different, fresh agent.
  • "Works" and "fixed" need evidence: test output, a command result or a screenshot.
  • End every task with a status: Done, Not done, Needs you.

Disagree with one? Override it in your own ~/.claude/CLAUDE.md, which loads alongside the core rules.

Skills

Skills are instructions the agent loads only when a task calls for them. You can name one directly or just describe the task; they also trigger on Polish phrasing.

Memory

brain-setup
Creates a vault from the template or connects your existing one, showing every config edit as a diff first.
brain-search
Answers "what did we decide about X?" from your notes only, citing each one.
brain-capture
Saves a decision, lesson or reference to the inbox, secrets redacted.
brain-review
Walks the inbox with you: promote, merge or reject the notes you name.
brain-garden
Health report: stale notes, broken links, bad frontmatter, likely duplicates.
brain-compile
Merges several notes on one topic into one compiled note, sources listed.

Engineering

spec
Interviews you, inspects the repo, writes a spec and plan, hands off to a fresh session.
code-review
Reviews a diff, commit or PR with P0–P3 findings and a merge verdict.
audit-to-backlog
Parallel specialist reviews with file-and-line evidence, turned into a backlog.
implement-backlog
Works through backlog items in small, validated, reviewed batches.
pr-cycle, fix-pr
Brings a PR to merge-ready, or addresses its review threads, asking before each fix and push.
bug-triage, deploy-checklist
Severity, reproduction and root cause; a GO/NO-GO list before a deploy.

Project hygiene

docs-sync
Checks docs against the code and reports drift.
project-baseline
Finds missing engineering practices and proposes them as backlog items.
instruction-review
Proposes a minimal, evidence-backed diff to your CLAUDE.md or AGENTS.md.
plan-status
Open, done and blocked counts, plus open decisions as A/B/C questions.

Session and communication

session-retro
End-of-session check for uncommitted work and running tasks, a status, and lessons worth keeping.
client-reply
Turns technical notes into a plain-language reply to a client. Drafts only, never sends.
skill-usage
How often each skill fired locally, with keep, merge or remove suggestions.

Also included: conventions skills for TypeScript, Next.js, tests, error handling, monitoring, comments and defensive coding (they load only when the task calls for them); reviewer agents for code, security, performance, QA and research; and output styles you can pick with /output-style.

Three hooks, and they only ask

The hooks are POSIX shell scripts with no dependencies and no network calls. They never block you outright: a guard asks for confirmation (in headless claude -p an ask becomes a denial), and on input it cannot parse it stays silent and the normal permission flow applies.

SessionStart

Loads the core rules. After a compaction or resume, adds a state card of at most 1 KB: branch, newest plan, task state, worktrees.

PreToolUse on Bash

Asks before a dependency install with a package argument, a force push, or a bypass of git hooks such as --no-verify.

Stop

Once per long session, suggests a wrap-up with session-retro. It reads tool-call counts and background-task ids, paths and times, never message content.

Get started

About five minutes, most of it in Obsidian settings.

  1. Install the plugin in Claude Code

    /plugin marketplace add msolecki/developer-os
/plugin install developer-os@developer-os

    There is no version number: an install takes the latest commit, and claude plugin update developer-os@developer-os picks up later ones.

  2. Set up the vault

    Ask Claude Code to run brain-setup. It creates a vault from the template or connects yours, then shows two config edits as a diff and applies them after you approve: a Brain vault: /path/to/vault line in ~/.claude/CLAUDE.md, and the vault path in permissions.additionalDirectories. An existing .obsidian/ folder is never overwritten.

  3. Enable two Obsidian core plugins

    Settings, Core plugins: turn on Bases and Templates, and set the Templates folder to templates.

  4. Try it

    Start a session and ask: brain-search webhooks. It should find the example note in the inbox.

For each project, copy templates/project/ into its root: an AGENTS.md both Claude Code and Codex read, a docs/ skeleton, and a .gitignore that keeps plans out of git.

To turn everything off, disable the plugin under /plugin.

What the vault looks like

Folders by topic, one frontmatter shape for every note, and nothing is ever deleted: retired notes move to _archive/.

FolderHolds
_inbox/New notes the agent captured, waiting for your review.
PROJECTS/One hub note per project, plus notes that outlive the repository.
DEV/Patterns and language or framework lessons.
TOOLS/References for tools, services and APIs.
INFRA/Hosting, deploys, networking, databases, CI.
QA/Testing approaches and lessons from defects.
_archive/Notes that are no longer true, merged or rejected.

Using Codex?

Codex support is manual and best-effort. From a clone of the repository, scripts/install-codex.sh --dry-run shows what would change, and running it without the flag copies the skills and the core rules into your Codex setup. The hooks, agents and output styles have no Codex equivalent. Details are in the README.
