Your coding agent forgets. Your vault doesn't.

developer-os is a Claude Code plugin that gives the agent an Obsidian vault as long-term memory, a short set of working rules for every session, skills for review, audits and pull requests, and hooks that ask before risky commands.

Plain Markdown and three small shell scripts. No server, no database, no telemetry. MIT licensed, free.

A rhythm, not another tool to babysit.

The plugin connects moments where you already make decisions. The full loop, with what goes where, is in How to work: brain + code.

  1. Start a task

    Search first

    Two minutes of brain-search routinely saves an hour of rediscovering a decision you already made. Finding nothing is useful too: you are in new territory.

    brain-search
  2. During work

    The plan lives in the repository

    Goal, decisions, steps, next action, updated after each step and git-ignored. Fast check before each commit, full suite before a push.

    docs/plans/
  3. A decision is made

    Capture it then

    The reasons are sharpest while the rejected options are still on screen. One note, one topic, into the inbox.

    brain-capture
  4. End of session

    Wrap up

    Unpushed work, running tasks, the status block, the plan, and up to three things worth keeping.

    session-retro
  5. End of day or week

    Review the inbox

    Keep, merge or reject each note. Nothing is promoted without you, and nothing is deleted: retired notes move to _archive/.

    brain-review
  6. Monthly

    Garden

    Stale notes, old inbox notes, broken links, duplicates and missing summaries, with fixes applied only after you approve.

    brain-garden

It proposes. You approve. Then it acts.

Every skill that changes files, git state or anything outside your machine stops at a defined point and asks. Silence or "looks good" is not approval. The full list is the approval model.

ActionWhat happens
Write in the vault outside _inbox/, move, merge or archive a noteOnly for the notes you name in brain-review or brain-garden
Delete a noteNo skill deletes; notes retire to _archive/
Edit ~/.claude/CLAUDE.md or settings.jsonbrain-setup shows the diff first
Edit code for review findings, commit, pushfix-pr asks per edit and per commit; pr-cycle asks once with A/B/C options, and before pushing
Merge a PR, push to a base branch, force-push, rebase a pushed branchNo skill does this
Send email, chat messages or issuesNo skill does this; client-reply drafts, session-retro prints a command for you
Install a dependencyA core rule, and the guard hook asks
SessionStart

Prints the core rules; after a compaction or resume, adds the state card of at most 1 KB.

PreToolUse on Bash

Asks before installs with a package argument, force pushes and git-hook bypasses. It never denies; in headless claude -p an ask becomes a denial.

Stop

Once per long session, suggests session-retro. Reads tool-call counts and background-task ids, paths and times, never message content.

All three are POSIX sh with no jq and no network calls, and they fail open: on an error they exit silently and the normal permission flow applies. Hooks reference, privacy, security policy.

Habits of a careful engineer, in every session.

An agent's defaults are not a careful engineer's. It commits without the right checks, claims "fixed" without evidence and reviews its own code. The core rules load at session start and stay under 8 KB, so they do not crowd out your own context.

Read core.md. Disagree with a rule? Override it in your own ~/.claude/CLAUDE.md, which loads alongside it.

  • Run lint, types and the changed area's tests before each commit; the full suite before a push or PR.
  • Never delete or skip tests to make a build green.
  • Write a plan before changing more than 50 lines of code, and keep it current so work survives a context reset.
  • Agent-written code is reviewed by a fresh agent that did not write it.
  • "Works" and "fixed" need evidence: test output, a command result or a screenshot.
  • One git worktree per parallel agent; one orchestrator pushes.
  • Open decisions are asked as A/B/C options, not assumed.
  • Every task ends with a status: Done, Not done, Needs you.

The skill library.

Grouped by the job in front of you. Each page says when the skill runs, what it does, what it writes, where it stops and what it never does.

Memory

Read and write the vault with the agent's own file tools.

  • brain-setupCreate a vault from the template or connect yours, with config edits shown as a diff.
  • brain-searchAnswer from your notes only, citing each one.
  • brain-captureSave a decision, lesson or reference to the inbox, secrets redacted.
  • brain-reviewWalk the inbox: promote, merge or reject the notes you name.
  • brain-gardenVault health report: stale notes, broken links, duplicates, orphans.
  • brain-compileSynthesize several notes on one topic into one compiled draft.

Engineering

Specs, reviews, audits, backlogs and pull requests, with evidence and approval gates.

  • specInterview, inspect the repo, write a spec and plan, hand off to a fresh session.
  • code-reviewP0–P3 findings and a merge verdict for a diff, commit or PR.
  • audit-to-backlogParallel specialist reviews with file-and-line evidence, as a backlog.
  • implement-backlogBacklog items in small, validated, reviewed batches.
  • pr-cycleMerge the base in, review, fix, gate and update a PR to a merge verdict.
  • fix-prAddress every unresolved review thread, approving each edit and push.
  • bug-triageSeverity, reproduction, ranked hypotheses and root cause.
  • deploy-checklistA GO/NO-GO checklist with post-deploy checks and rollback.

Project hygiene, session and communication

Keep docs, instructions and plans honest; end sessions cleanly; talk to clients plainly.

  • docs-syncDocs against code: scaffold, refresh the current state, report drift.

  • instruction-reviewA minimal, evidence-backed diff to CLAUDE.md or AGENTS.md.
  • plan-statusMeasured open, done and blocked counts, and open A/B/C decisions.

Specialists that report, and a second pair of eyes.

Skills dispatch these agents for independent passes, and you can call them yourself. A reviewer that did not write the code is a core rule, not a nice-to-have.

  • code-reviewerCorrectness, security, data safety and maintainability, rated P0–P3 with a merge verdict.
  • security-auditorExploitable defects: auth, injection, secrets, SSRF, insecure defaults.
  • performance-engineerMeasured defects: N+1 queries, blocking I/O, serial awaits, bundle bloat.
  • qa-expertTest quality and coverage gaps, and the missing tests when asked.
  • research-analystSourced answers on libraries, API contracts, vendor limits and migrations.
  • Output stylesarchitect, debug, direct-objective and tdd-enforcer, selected with /output-style.

The vault is plain Markdown you own.

Folders by topic, one frontmatter shape for every note, and Bases views for the inbox and stale notes. Nothing is ever deleted. brain-setup creates it from the template or connects your existing vault without touching your .obsidian/ folder.

Vault layout and note format, writing a note that will be found.

FolderHolds
_inbox/New notes the agent captured, waiting for your review
PROJECTS/One hub note per project, plus notes that outlive the repository
DEV/Patterns, language and framework lessons
TOOLS/References for tools, services and APIs
INFRA/Hosting, deploys, networking, databases, CI
QA/Testing approaches and lessons from defects
_archive/Notes no longer true, merged or rejected

It fits if…

  • you work with Claude Code across several client or product repositories, alone or in a small team;
  • you want decisions and lessons to outlive a session and a repository;
  • you are happy to review what the agent captures before it counts as knowledge;
  • you want the agent to plan, check and ask the way a careful engineer would.

Look elsewhere if…

  • you want memory that writes itself with no review: approval is the point;
  • you need a server, a search index or a shared team knowledge base: there is no runtime;
  • you want agents to merge, push to a base branch or send messages on their own: no skill does;
  • you work mainly in Codex: support there is a best-effort installer without hooks, agents or output styles.

Get started in about five minutes.

  1. Install the plugin in Claude Code

    /plugin marketplace add msolecki/developer-os
/plugin install developer-os@developer-os

    An install takes the latest commit; claude plugin update developer-os@developer-os picks up later ones. Auto-update is off unless you turn it on under /plugin.

  2. Set up the vault

    Ask Claude Code to run brain-setup. After you approve the diff it adds a Brain vault: /path/to/vault line to ~/.claude/CLAUDE.md and the vault path to permissions.additionalDirectories.

  3. Enable two Obsidian core plugins

    Settings, Core plugins: Bases and Templates, with the Templates folder set to templates.

  4. Try it

    Start a session and ask: brain-search webhooks. It should find the example note in the inbox.

For each project, copy templates/project/ into its root. Full setup guide

Before you install.

Does it send my code or notes anywhere?

The plugin sends nothing by itself and its hooks make no network calls. What the agent reads from the vault goes to your model provider as part of the session, like any file it reads. brain-capture redacts secrets before writing; review inbox notes for client names and personal data before you promote them. Privacy

Does it change how Claude behaves in all my projects?

Yes. The core rules load into every session in every project. Override a rule in your ~/.claude/CLAUDE.md, or disable the plugin under /plugin.

Can I use it without a vault?

Yes. The engineering and session skills, the agents and the hooks work on their own. The brain skills ask once for the vault path and stop if you have none, and the core rules run brain-search only when a Brain vault: line exists.

Can a hook block a command?

No. The guard only asks, and on input it cannot parse it stays silent. In headless claude -p there is no one to ask, so an ask resolves to a denial.

How much context does it cost per session?

The core rules are capped at 8192 bytes and all skill descriptions at 12000 characters in total; scripts/check.sh fails a change that grows past either. Skill bodies load only when a skill runs.

Is it stable?

It is not released yet: installs track the development branch, with no version number. Current state lists what works and what is known to be missing, and the changelog lists every change.

Which languages does it understand?

Skill descriptions carry English and Polish trigger phrasings, so a skill fires however you ask in either language. The core rules keep the conversation in your language, whatever it is, and keep everything written to a repository in English unless the project says otherwise.
