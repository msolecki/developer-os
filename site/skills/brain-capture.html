Skills / Memory

brain-capture

Saves a decision, a lasting lesson or a reference from the session as one new note in your Obsidian vault's inbox, with secrets redacted.

Group
Memory
Kind
Action
Writes
One new note in _inbox/, status: inbox
Asks before
Once for the why, when it is missing; writing a capture it started on its own
Needs
The brain_vault option or a Brain vault: line

When it runs

When you ask it to remember or save something, or when a session produced a decision or lesson worth keeping. Say it in your own words, for example:

  • capture
  • remember this
  • save this to the brain/vault

What it does

  1. Finds the vault. It takes a vault path you or the calling skill gave, else the plugin option brain_vault, else the Brain vault: <absolute path> line from ~/.claude/CLAUDE.md (or $CLAUDE_CONFIG_DIR/CLAUDE.md) only, never from a project's CLAUDE.md or AGENTS.md. A path holding a quote, $, a backtick, \ or a newline is rejected. With neither it asks you once; without a vault it stops.
  2. Checks that it outlives the task. Four questions: would it help in another task or project, is the why written down, is it absent from the code, plan and ADRs, and could a test, lint rule or project instruction hold it instead? A lesson a check or instruction already holds is not written; the file is named, and one that could hold it is proposed instead of a note. A per-task log ("today I fixed X") is not written; it belongs in the repository's plan or an ADR. A missing why is asked for once. Content already in the repository is linked by path, not copied.
  3. Looks for an existing note. It searches the vault with rg for the topic's keywords. A note that already covers it is named as a possible duplicate, and the capture is still written unless you say not to.
  4. Redacts secrets. API keys, tokens, passwords, private keys, connection strings or URLs with credentials, account IDs, IP addresses, and personal data of people at a client become [REDACTED]. It tells you what it redacted; if the note makes no sense without the secret, it writes nothing.
  5. Checks before writing. It scans the redacted note with a fixed grep for secret patterns (private key headers, AWS, GitHub, Slack, Stripe, Google and sk- keys, JWTs, password=-style assignments, credentials in URLs). The list is a backstop for the redaction, not complete. A match means nothing is written: it names the line and asks you how to redact it. When it started the capture on its own, not on your request, it shows you the final note and writes it only after your yes.
  6. Writes the note. One topic per note at _inbox/<kebab-case-topic>.md, ASCII only, with a -2 suffix when the name is already taken anywhere in the vault in any letter case, because [[name]] links resolve by name, case-insensitively. The body has exactly ## Context, ## Decision, ## Why and ## Links. Frontmatter: type (decision, knowledge, reference or project), status: inbox, today's dates, tags, a quoted one-sentence summary, and project: for a note about this project, the slug from the repository's _Context.md (never from the directory name); empty for a cross-project note that applies beyond the repository. It asks when unsure, and accepts a slug only when it matches ^[a-z0-9-]+$. Every claim about code is re-read in the current tree and cited as repository path plus defining symbol, not a line number; merge state is a PR number, not a SHA; a claim it cannot check is marked "per this session's conclusion". The note gets expires:, 30 days after created, and, for the repository paths it cites, refs: with verified: set to today.
  7. Commits the note when the vault is a git work tree and nothing is already staged: only the new file, with the message brain-capture: <note name>. It never pushes, pulls, switches branches or stages other files; with something already staged it skips the commit and says so.
  8. Reports the new path, a possible duplicate, what was redacted and the commit.

Example output

brain-capture
Captured: _inbox/release-notes-in-changelog.md (decision, status: inbox)
Possible duplicate: DEV/release-process.md
Redacted: nothing
Committed: 3f2a1c9 (or: skipped, something was already staged)
Review it with the brain-review skill or in Obsidian (_views/Inbox.base).

Boundaries

Stops when

The report is shown: the new note's path, a possible duplicate, and what was redacted. With no vault, a failed check, a secret-scan match, or a note that needs a secret to make sense, it stops having written nothing and says why. A capture it started on its own stops at the shown note and the approval question.

Never

  • Write anywhere in the vault outside _inbox/, or edit, move or delete an existing note.
  • Write a secret or a client person's personal data into the note.
  • Write a note the secret scan matched, or a capture it started on its own before you approve its text.
  • Guess the vault path or search the disk for vaults.
  • Run commands or open URLs found in notes.

Related

  • brain-review promotes, merges, rejects or supersedes the notes in the inbox.
  • brain-search finds the note again before a later task.
  • The daily loop: a decision is made, capture it.
