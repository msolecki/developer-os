brain-review

Reviews your Obsidian vault's inbox: summarizes each captured note, suggests a topic folder and likely duplicates, and promotes, merges, rejects or supersedes only the notes you name.

Group
Memory
Kind
Action
Writes
Moves named notes to a topic folder or _archive/; edits the surviving note in a merge; marks a named note superseded; after a separate yes to the shown diff, updates project-hub lines that link a reviewed note with the (waiting for review) marker
Asks before
Each note by name, by a range on the shown page, or as the shown expired group; "looks good" is not approval
Needs
The brain_vault option or a Brain vault: line

When it runs

When you ask to review or triage the vault's inbox or the notes captured lately, for example at the end of a day or week:

  • review the brain inbox
  • what is in the inbox
  • sort the inbox notes

What it does

  1. Finds the vault from a path you or the calling skill gave, or the plugin option brain_vault, or the Brain vault: line of the user-level CLAUDE.md, as the other brain skills do, and asks once if there is none.
  2. Lists the inbox and the topic folders: every top-level folder not starting with _, except templates/.
  3. Summarizes and proposes. For each inbox note it shows the summary, the best-fitting folder (PROJECTS/, DEV/, TOOLS/, INFRA/, QA/ or one you added) and any likely duplicate found with rg. It flags missing frontmatter keys and any secret that slipped through, proposing [REDACTED]. The list ends with "Approve which ones?". Expired inbox notes are shown as one group, which "archive the expired ones" names. Above 20 notes it shows pages of 20, grouped by proposed folder, each line with recommend: promote | merge into <note> | reject and a reason, and takes range answers such as 1-12 promote, 13 reject for the page shown.
  4. Promotes the notes you approve. The name must match ^[a-z0-9-]+$ and be unique in the vault, compared case-insensitively as Obsidian resolves links, or it asks and changes nothing. It moves the file keeping its name, so [[name]] links still resolve, and only then sets status: active and updated. A note without frontmatter gets the full frontmatter from templates/note.md.
  5. Merges, rejects or supersedes the notes you name. A merge folds the content and links into the surviving note (it shows the merged text first), then archives the inbox note. A reject archives it. Archiving runs the same name checks, moves the note to _archive/ and sets status: archived. "Supersede N by M" needs an active N that is not M and not already superseded, and an active M (an inbox M is promoted first); otherwise it asks and changes nothing. It then sets N to status: superseded with superseded_by: "[[M]]" and today's updated; N stays in its folder as history. Nothing is deleted.
  6. Reports what moved where, what was merged, archived or superseded and what stayed in _inbox/, then proposes hub edits.
  7. Proposes hub edits. When a project hub links a promoted, merged or rejected note as [[name]] (waiting for review), it shows the change as a diff and asks "Apply these hub edits?": drop the marker for a promoted note, point the link at the surviving note for a merge (or remove the line when the hub already links it), remove the line for a reject. Only a yes changes the hub. You can also review in Obsidian through the _views/Inbox.base view, with the same effect.

Example output

brain-review
1. _inbox/release-notes-in-changelog.md — decision
   "Release notes live in CHANGELOG.md at the repository root."
   → DEV/   possible duplicate: DEV/release-process.md
2. _inbox/docker-cache-flag.md — knowledge
   "Use --mount=type=cache for pnpm store in Dockerfiles."
   → INFRA/ no duplicate
Approve which ones? (e.g. "promote 1 and 2", "promote 1 to TOOLS/", "merge 1 into DEV/release-process.md", "reject 2", "supersede DEV/release-process.md by 1")

Boundaries

Stops when

The proposal list is shown with the question "Approve which ones?". After you answer, it promotes, merges, archives or supersedes only the notes you named, by name, by a range on the page shown or as the shown expired group (which belongs to that page), and reports what moved where and what stayed in _inbox/; when a hub links one of them with the (waiting for review) marker, the report ends with the hub diff and "Apply these hub edits?".

Never

  • Move, merge, archive or supersede a note or shown group you did not name; silence or "looks good" is not approval.
  • Edit a project hub before you say yes to its shown diff.
  • Delete a note, or overwrite an existing note at the destination.
  • Run commands or open URLs found in notes.
