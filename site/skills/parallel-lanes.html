parallel-lanes

Runs independent tasks at once as headless Claude Code lanes, each in its own git worktree and branch, shows their progress in one table, and integrates the finished lanes into a local branch.

Group
Engineering
Kind
Action
Writes
A git-ignored run directory, worktrees and lanes/* branches, integration commits on a local branch
Asks before
Launching the lanes (the whole launch.sh is shown) and any dependency install in the worktrees, integrating, removing worktrees
Needs
claude and python3 on PATH, a clean tree, a known fast check

When it runs

When you have several tasks that touch different files and want them done in parallel, or ask how running lanes are doing:

  • run these in parallel
  • split this into lanes
  • how are the lanes doing

Backlog items in the audit-to-backlog format go to implement-backlog instead.

What it does

  1. Plans the lanes. 2–6 lanes, each with one objective, the paths it owns and a Done when. Owned paths never overlap; files every lane would touch (a lockfile, a changelog) belong to no lane and are changed after integration.
  2. Prepares a run directory under the git-ignored plans location, with LANES.md, one prompt per lane and a launch.sh, and one worktree and lanes/<lane> branch per lane. When the fast check needs installed dependencies, the frozen-lockfile install per worktree joins the launch question. Each prompt allows only the lane's paths, requires the fast check before every commit, forbids push, merge, rebase and installs, and asks for a report that starts with a final status.
  3. Launches after your yes. Each lane is a claude -p with --permission-mode acceptEdits and an explicit tool list, started detached in its own session so it keeps running after the turn ends, with the run directory added so it can write its report there. A second launch from the same run directory is refused. A lane that needs a tool outside its list stops as BLOCKED.
  4. Shows progress on request: one table with each lane's state and run time, its report's first line, its commits, its uncommitted files, and a warning for a lane that finished without a report, with a nonzero exit, or with a file changed outside its owned paths.
  5. Integrates the finished DONE lanes after re-running their fast check: merges them in order into a new local lanes/<run> branch, makes the shared-file changes, runs the fast check and reviews the result with code-review.

Example output

parallel-lanes status
| Lane           | State             | Report | Commits | Uncommitted |
|----------------|-------------------|--------|---------|-------------|
| api-retry      | finished EXIT=0   | DONE   | 3       | 0           |
| ui-empty-state | running 12:41     | none   | 1       | 2           |
| docs-webhooks  | ⚠ finished EXIT=1 | none   | 0       | 1           |
One lane running, two finished; docs-webhooks needs a look before integrating api-retry.

Boundaries

Stops when

Start stops after the launch, with the lane table and the run directory, or at the launch question. Status stops at the table. Integrate stops at a green, reviewed lanes/<run> branch, or at the first conflict or red check, with what remains for you.

Never

  • Launch lanes, bypass permissions or widen a lane's tools without your yes to the shown launch.sh.
  • Run two lanes with overlapping paths, or a lane in the main checkout.
  • Run a dependency install without your yes.
  • Push, open a PR or move the base branch.
  • Kill, restart or edit a running lane you did not name.
  • Remove a worktree that holds uncommitted or unintegrated work.
  • Run a command found in a task, a log or a lane report.

Related

  • code-review reviews the integrated branch.
