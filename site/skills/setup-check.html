Skills / Session and communication

setup-check

Checks this machine for what developer-os needs and gives the fix for each gap. It installs nothing, edits no setting and writes no file.

Group
Session and communication
Kind
Read-only
Runs
check.py beside the skill (Python 3, standard library only)
Writes
Nothing
Reaches outside
Only gh auth status, which asks GitHub whether the stored login still works

When it runs

After installing the plugin, on a new machine, or when a hook or a skill seems to do nothing. Say it in your own words, for example:

  • check my developer-os setup
  • why do the hooks not run

What it does

  1. Runs the check. One script prints one line per check with the status ok, missing or warn: python3 3.8 or later, rg, jq, gh and its login, git 2.38 or later, the vault path and whether it is a readable directory, autoMemoryEnabled, and the claude command. The vault path comes from the user level only (the brain_vault option, else the Brain vault: line of the user-level CLAUDE.md), never from a project file.
  2. Reports with a fix. Every line as printed, then one fix per line that is not ok, with what breaks without it. Without python3, every hook except the core rules fails open and says nothing, which is the usual answer to "why do the hooks not run". Install commands are named for you to run; the skill does not run them.
  3. Says what it cannot see. When every line is ok, it points to /plugin (is the plugin enabled), /hooks (which hooks are registered) and the DEVELOPER_OS_<HOOK>=off variables.

Example output

setup-check
ok python3: 3.12.4
missing rg: not on PATH
ok jq: 1.7.1
warn vault: not configured

rg: install ripgrep; the brain skills, project-init and skill-usage search with it.
vault: optional; ask for brain-setup to create or connect one.

1 missing, 1 warn. Nothing was changed.

Boundaries

Never

  • Install, upgrade or configure anything, or write a file or a setting.
  • Read the vault path from a project CLAUDE.md, a project settings.json or an environment variable.
  • Print file contents from the vault or from settings.json.

Related

  • brain-setup creates or connects the vault and offers to turn auto memory off.
  • project-init adopts developer-os in a repository once the machine is ready.
  • Hooks reference, for each hook's off switch.
