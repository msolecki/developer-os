brain-import-memory

Moves one project's Claude Code auto memory into your Obsidian vault: it checks each memory file against the vault, proposes what to do with it by number, and applies only the numbers you name.

When it runs

When you turn auto memory off, or brain-setup reports auto-memory files:

  • import my auto memory
  • move memory to the brain
  • brain-setup found memory files

What it does

Claude Code's auto memory keeps one folder per project and machine, written without review, with its MEMORY.md index loaded into every session. developer-os keeps long-term knowledge in the vault (decision D24), so this skill drains that folder into the vault once, with the same gate as brain-capture.

  1. Finds the vault from the Brain vault: line, in the same order as the other brain skills.
  2. Finds the memory folder: <config>/projects/<project>/memory/, named after the repository's main checkout (so every worktree finds the same folder) with every non-alphanumeric character as -, or autoMemoryDirectory from the local, project or user settings (a leading ~/ is expanded). When it is missing or empty, it lists the projects that have memory files with their counts and asks which one; with all projects, it handles one folder at a time.
  3. Reads and checks each file except MEMORY.md, which it reads only to report an index line whose file is missing. It searches the vault for each file's topic, reads the matching notes and gives the file one label: covered (a note, the user-level CLAUDE.md, its rules/ or the project's instruction file already says it), add (sentences for an existing note), new (an inbox note in brain-capture's format; files on one topic make one note), preference (a line for the user-level CLAUDE.md), project-rule (a line for the repository's instruction file) or skip (with the reason). A file that contradicts a note shows both claims; the newer, better-evidenced one is proposed, otherwise the note stays. Secrets, account IDs, IP addresses and private contact details become [REDACTED].
  4. Shows the list and asks, with each new note in full and each addition as a diff.
  5. Applies the numbers you name: new notes in _inbox/ after brain-capture's secret scan, with an ASCII file name that is free across the vault and status: inbox; additions to the named notes with updated set to today; preference lines appended to CLAUDE.md; the project diff. The memory files stay where they are.
  6. Turning auto memory off is one of the numbers: while autoMemoryEnabled is not false, the list ends with a setting item, previewed as a diff without writing anything. On approval it validates the new settings.json before copying it over the original; on invalid JSON or without jq it changes nothing and shows the key. CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 in the environment also turns it off and wins over the setting, so the item is left out when it is set. After writing, it re-checks: when a project settings file still turns auto memory on, it names that file.

Boundaries

Stops when

At the numbered list with "Apply which?". After you answer, it applies only those numbers and reports each file it created or changed, the conflicts left open, the memory folder (untouched) and whether auto memory is now off, from that re-check.

Never

  • Delete, move or edit a memory file, or MEMORY.md.
  • Write or edit any file, temporary files included, before you name its number, or edit a vault note you did not name.
  • Create a note outside _inbox/, or promote, move or archive a vault note.
  • Copy a secret, token, key, account ID, IP address or private contact detail into the vault or an instruction file.
  • Combine several projects' memory into one list, or search the disk for memory folders beyond <config>/projects/*/memory and the configured autoMemoryDirectory.
